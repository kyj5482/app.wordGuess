# Word Guess — 설계 문서 (PoC 기준)

> 작성일: 2026-08-03 · 근거: 01-requirements, 02-benchmark, 03-tech-research, 04-word-db-spec

## 1. 단계 전략

| 단계 | 목표 | 범위 |
|---|---|---|
| **PoC (지금)** | GitHub Pages에 배포해 UI/UX·모션 조작·힌트 흐름이 원하는 것인지 실기기로 점검 | 카테고리 선택 → 라운드 플레이(모션/탭) → 2단계 힌트 + 시간 감점 → 결과 화면. 단어 DB 1,000+ |
| 본 개발 | PoC 피드백 반영 후 정식 구현 | 그룹 캘리브레이션, 참가자 프로필/개인 맞춤 난이도, PWA 오프라인, 다국어 UI |
| 앱 배포 | 스토어 출시 | Capacitor 래핑 (orientation lock·햅틱 등 웹 제약 해소) |

PoC는 **프레임워크 없는 바닐라 JS + 정적 파일**로 만든다. 빌드 도구 없이 GitHub Pages에 바로 배포 가능하고, 점검 후 본 개발에서 스택(예: Vite + TypeScript)을 확정한다. 모션 감지·게임 로직은 모듈로 분리해 본 개발에서 그대로 이식한다.

## 2. PoC 아키텍처

```
/ (repo root = GitHub Pages 루트)
├── index.html            # 단일 페이지, 화면(screen) 전환 방식
├── css/style.css
├── js/
│   ├── app.js            # 화면 라우팅, 게임 세션 상태
│   ├── words.js          # 단어 로드·병합·카테고리 질의·셔플
│   ├── tilt.js           # 모션 제스처 상태 머신 (핵심 모듈)
│   ├── round.js          # 라운드 타이머, 정답/스킵/힌트 처리, 점수
│   └── sound.js          # WebAudio 효과음 (정답/스킵/힌트/카운트다운)
├── data/words/*.json     # 도메인별 단어 DB (fetch로 로드)
├── scripts/validate-words.mjs   # 단어 DB 검증 (개발용)
└── docs/                 # 설계 문서
```

- 서버·빌드 없음. `fetch('./data/words/*.json')`로 로드 (상대 경로 → 서브패스 안전).
- 상태는 메모리 + `localStorage` (마지막 선택 카테고리/레벨/시간 설정 기억).

## 3. 화면 흐름

```
[홈] ──> [카테고리 선택] ──> [레벨·시간 설정] ──> [준비 화면] ──> [라운드] ──> [결과]
                                                     │(폰을 이마로: 3-2-1)      │다음 사람
                                                     └──────────<──────────────┘
```

1. **홈**: 타이틀 + "시작" 버튼. *이 탭 제스처에서* 모션 권한 요청 + AudioContext resume + Wake Lock 획득 (기술조사 §4 결론).
2. **카테고리 선택**: 기본 태그 20종 카드 그리드 + "전체 랜덤". 각 카드에 단어 수 표시.
3. **설정**: 레벨 (K–2 / 3–5 / 섞기), 라운드 시간 (45/60/90/120초 — 벤치마크에서 60초 고정이 1위 앱의 문서화된 불만이므로 조절 가능이 차별점).
4. **준비 화면**: "폰을 이마에 대세요" (가로 방향 안내 포함). 세로면 회전 안내 (`matchMedia('(orientation: portrait)')`, iOS는 lock 불가하므로 안내만).
5. **라운드**: 큰 글씨 단어 + 타이머 + 힌트 영역. 카운트다운 종료 시점 각도로 중립 캘리브레이션.
6. **결과**: 점수, 단어별 정답/스킵/힌트 사용 리뷰, "다음 사람" / "카테고리 바꾸기".

## 4. 모션 제스처 설계 (핵심)

기술 조사 §2.2 상태 머신을 채택한다. 요약:

- **입력**: `devicemotion`의 `accelerationIncludingGravity` (짐벌 락·gamma 랩어라운드 회피, landscape 부호 보정 단순). orientation 이벤트는 미지원 기기 폴백.
- **판정 v4 (버전 회귀 분석 후 확정)**: v1 구조가 기준, 속도는 가속 전용.
  - **기본 경로 (v1 복원)**: 위치(중립 대비 기울기) |Δ| ≥ 6.5 m/s² → 즉시 판정. 위/아래 대칭.
  - **가속 경로**: |Δ| ≥ 5.0 이면서 같은 방향 속도 ≥ 25 m/s²/s → 조기 판정. 속도는 ~90ms 슬라이딩 윈도우 기울기로 계산 (iOS 버스트 배달·노이즈에 안정). **속도는 무언가를 막는 데 절대 쓰지 않는다.**
  - **재무장은 위치만**: 중립 밴드(<3 m/s²) 150ms 체류 → 재무장. 복귀 스윙 오판은 800ms 쿨다운이 흡수.
  - **중립 기준선**: 라운드 시작 캘리브레이션 + ARMED 중립 체류 중 저역 통과 미세 추종 (팔 처짐 흡수 — v1 기능, v3에서 제거했다가 복원).
  - 교훈 (버전 이력): v2의 "임계값 상향+지속 조건"은 보통 속도 동작을 놓침(6회 중 3회). v3의 "재무장 속도 조건"은 손떨림에서 재무장을 최대 2.5초 지연시켜 다음 동작을 삼킴 — "점차 나빠진다"는 체감의 원인. 판정·재무장은 위치 신호만, 속도는 가속에만 쓸 것.
  - 검증: 3버전 동일 신호 시뮬레이션(50Hz, 노이즈·불규칙 간격·iOS 버스트·떨림 ±2 m/s²) — v4는 전 조건 miss 0 / wrong 0 / ghost 0, 평균 지연 v1 대비 단축.
- **진동 피드백** (화면을 못 보는 플레이어의 촉각 채널, Android 한정): 정답 = 길게 1회(250ms), Skip = 짧게 3회, **재무장 완료 = 미세 진동(30ms)** — 다음 동작을 해도 된다는 신호. iOS는 사운드로 동일 정보 전달.
- **제스처 매핑**: 아래로 기울임 = 정답, 위로 젖힘 = Skip (업계 표준 관례 유지, 임계값은 젖힘 쪽을 더 낮게 — 가동 범위 비대칭).
- **피드백**: 정답 = 초록 플래시 + 상승음, Skip = 주황 플래시 + 하강음, 힌트 = 파랑 + 알림음. 이마에 대고 있어도 소리로 구분 가능. Android는 진동 추가.
- **폴백 3경로** (기술조사 §3): API 부재 / iOS 권한 거부 / 이벤트 미수신(1.5초) → 탭 존 모드 (화면 위쪽 절반 탭 = Skip, 아래쪽 절반 = 정답). 모션 모드에서는 탭 존을 비활성화한다 — 이마에 댄 폰에 손가락·이마가 닿아 오입력될 위험이 병행 활성의 이점보다 크다.

## 5. 힌트 시스템 설계

**누가 발동하는가**: 폰을 든 사람(맞추는 사람)은 화면을 볼 수 없으므로, 힌트는 **설명하는 친구가 발동**한다. 모션이 아니라 **화면의 힌트 버튼을 탭** — 설명자들은 화면을 보고 있으므로 탭이 자연스럽고, 모션 채널(정답/Skip)과 분리되어 오작동 여지가 없다. (요구사항의 "모두 모션 기반" 취지는 "쉽고 직관적인 조작"이므로, 화면을 보는 사람에게는 탭이 더 직관적이라 판단. PoC에서 검증.)

- **힌트 1회 (단어당)**: `emoji`가 있으면 **그림+텍스트 함께**, 없으면 텍스트만 — 그림 단독 노출은 없음 (1차 PoC 피드백: 그림만으로는 설명이 어려움). 설명자가 떨어져서 보므로 힌트 텍스트는 크게 표시.
- **시간 감점**: 힌트 1회당 **−5초** (라운드 시간에서 즉시 차감 — 화면에 감점 애니메이션 표시). 결과 화면에 단어별 힌트 사용 표시.
- 감점으로 남은 시간이 0이 되면 라운드 종료.

## 6. 단어 서비스 (words.js)

- 전 JSON 병합 → `word` 중복 시 태그 합집합 (DB 스펙 §5).
- 카테고리 질의: `tags.includes(tag) && level <= maxLevel`.
- 셔플: Fisher–Yates. 세션 내 출제 단어 기록 → **같은 세션에서 재출제 금지** (벤치마크의 "카드 반복" 불만 대응). 덱 소진 시에만 리셋.
- 카테고리 카드에 단어 수 노출 → 너무 적은 조합(< 20개)은 경고 표시.

## 7. 본 개발 이월 항목 (PoC 제외)

- 그룹 캘리브레이션 (FR-13) — PoC에서는 레벨 수동 선택으로 대체. 흐름 검증 후 설계.
- 참가자 프로필·개인 맞춤 난이도 (FR-14) — 로컬 프로필 스키마는 본 개발에서.
- PWA (service worker, manifest, 오프라인) — PoC는 온라인 전제.
- 다국어 UI, 유아(level 0)~성인(level 4) 단어 확장, 이모지 → 일러스트 교체.
- Capacitor 패키징.

## 8. 리스크와 검증 계획

| 리스크 | 대응 | PoC에서 확인할 것 |
|---|---|---|
| iOS 권한 거부 캐시 | 시작 버튼 제스처에서 요청, 거부 시 탭 모드 안내 | 실기기: 거부 후 재요청 동작 |
| 수직 자세 센서 불안정 | gravity z축 + 캘리브레이션 델타 | 실기기: 부호 방향, 임계값 튜닝 |
| 더블 트리거 | 히스테리시스+쿨다운+중립 래치 | 실기기: 연속 빠른 플레이에서 0건인지 |
| 화면 꺼짐 | Wake Lock (iOS 16.4+) | 구형 기기 폴백 필요 여부 |
| 힌트 UX 가설 | 설명자 탭 방식 | 실제 플레이에서 자연스러운지 |
